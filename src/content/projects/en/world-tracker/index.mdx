## What it does

World Tracker lets multiple users keep a personal log of the countries they have
visited. A user types a country name, the server validates it against a
canonical countries table — exact, then begins-with, then contains, using
`ILIKE` — and if valid, saves it to that user and highlights the corresponding
country on a world map rendered with EJS.

## Key features

- Multiple users, each with their own set of visited countries
- Server-side validation against a canonical table (exact → begins-with → contains)
- Duplicate protection with clear success and error feedback
- Dynamic map rendering that colours visited countries and updates totals

## Tech stack

Node.js, Express, PostgreSQL, EJS, and vanilla JavaScript.

## My role & challenges

I built the full stack: the EJS views, the Express routes, and the PostgreSQL
queries. The main challenges were text matching for country inputs — balancing
`ILIKE` strategies for exact versus partial matches — keeping query performance
acceptable, and preventing duplicates per user with unique constraints. I also
implemented user switching and used parameterised queries throughout.

## What I learned

- EJS templating patterns for conditional rendering and partials
- Designing clean Express routes with server-side validation
- Parameterised queries and basic text-lookup indexing in PostgreSQL
- Conflict handling with `ON CONFLICT DO NOTHING` and unique-per-user logic
